# 行李清单

手机端出游打包清单：**必带 / 选带**两个物品池，出发前建一份清单逐项打勾清点，常用的组合可以存成模版反复套用。

**在线使用**：https://yongshenglu.github.io/travel-packing/

纯静态网页，无构建步骤，无第三方依赖，无统计无追踪。

- 页面：公开仓库 [yongshenglu/travel-packing](https://github.com/yongshenglu/travel-packing) → GitHub Pages
- 数据：保存在你自己 GitHub 账号的**私有仓库**里，也可只存在本机

---

## 用法

### 物品池
「物品池」页里，必带和选带在同一屏上下排列，各自可搜索、添加、删除。点物品名可改名或把它挪到另一个池。想调整顺序时，**长按某个物品约 0.25 秒**，它会「抬起」，然后拖到想要的位置松手即可；顺序会跟着数据一起同步到其它设备。

### 新建清单
顶栏「＋ 新建」：

- 默认打开**「自动带入必带物品」**，创建后必带池的物品会全部进清单，之后仍可单独移除
- 可选一份模版；选中模版后，模版里的物品会成为清单基础，自动带入会补齐模版里没有的必带物品
- 选带物品在弹层里多选

### 清点
清单页顶部是进度环和筛选条（全部 / 未打包 / 已打包 / 必带 / 选带），整行点按即可勾选。每行右侧有数量标记，默认是 `×1`；点它会原地变成 `− ＋` 步进器，直接改完再点数字收起（比如充电宝带 2 个）。行尾的 `×` 可以把该物品从清单里删掉，删除前会确认并带上物品名；已打包的行会带浅青底色和删除线，便于扫读。底部四个操作：

| 按钮 | 作用 |
|---|---|
| 存为模版 | 把当前清单存成新模版 |
| 更新模版 | 用当前清单的物品覆盖一份已有模版 |
| 全部重置 | 取消所有勾选 |
| 删除清单 | 删除这份清单 |

点清单标题可改名，点出发日期可设置或修改。

### 模版
模版详情页可「用此模版建清单」「从清单更新」「编辑物品」，底部可删除模版。

## 多设备同步

数据同步到你自己 GitHub 账号下的**私有仓库**，浏览器通过 GitHub Contents API 读写 `data.json`。

### 隐私

- 访问令牌（PAT）**只保存在本机浏览器的 localStorage**，不会上传到任何第三方服务器，代码里也不会硬编码
- 应用页面放在公开仓库，**清单数据放在私有仓库**，只有你有权访问
- 打开设置页可以看到同步相关说明

### 配置步骤（每台设备做一次）

1. 在 GitHub 新建一个**私有仓库**，建议命名 `travel-packing-data`，初始化时勾选 **Add a README file**
2. 在 [Settings → Developer settings → Personal access tokens → Fine-grained tokens](https://github.com/settings/personal-access-tokens/new) 生成令牌：
   - **Repository access**：Only select repositories → 选中刚建的数据仓库
   - **Permissions → Repository permissions**：只给 **Contents** 设为 **Read and write**
3. 在本应用「设置」页填入 GitHub 用户名、数据仓库名、令牌，点「保存配置」，再点「测试连接」确认可用
4. 保持「自动同步」开启：改动后约 5 秒自动推送；打开应用或回到前台时会自动拉取

### 合并规则

多台设备同时修改时按实体级「最后修改者优先」合并，并用墓碑记录删除，所以：

- 一台设备新增的物品，另一台能拿到
- 一台设备删除的物品，删除会传播到其它设备
- 两台各自勾选不同的物品，勾选结果都会保留

极少数情况（同一秒、同一物品被两台设备改成不同内容）才会取其中一份，不会再弹出「本地/云端二选一」的对话框。

## 预设物品

物品池最下方有「**保存为预设物品**」，会把当前必带 + 选带的整套内容记成你自己的预设。
之后设置页的「恢复预置物品」就恢复到这一份，而不是内置的那份。

- 存了自定义预设后，设置页的按钮会显示「恢复预置物品（自定义）」，下面多一个「回到内置预设」
- 「恢复预置物品」是**先清空两个池再填入**，不是往里追加

## 数据备份

设置页底部可：

- **导出 JSON**：把整份数据下载成本地文件
- **导入 JSON**：从备份文件恢复（会覆盖当前数据）
- **恢复预置物品**：清空两个物品池，按当前生效的预设重新填入
- **回到内置预设**：丢掉自定义预设，改回应用自带的那份
- **清空本机数据**：清空本机所有内容（建议先导出备份）

## 开发

```
index.html        页面外壳
styles.css        全部样式
js/main.js        入口：启动、事件、同步状态
js/store.js       数据模型、localStorage、预置数据
js/merge.js       多设备合并（LWW + 墓碑）
js/sync.js        GitHub Contents API 同步
js/views.js       各屏渲染与交互
js/ui.js          转义、提示、弹层、日期格式化
sw.js             Service Worker
manifest.json     PWA 清单
icons/            应用图标
```

本地预览（ES modules 需要走 http，不能直接双击打开）：

```bash
python serve.py
```

然后访问 `http://127.0.0.1:8010`。

`serve.py` 会带上 `Cache-Control: no-store`，**改完代码刷新就能看到**；直接用
`python -m http.server` 的话，浏览器可能拿两三分钟内的旧文件，改了像没改一样。

### 修改后必须做的事

`sw.js` 顶部有常量 `VER`。**每次改动 HTML / CSS / JS 后都要把 `VER` 递增**（例如 `tp-v3` → `tp-v4`），
否则已经装到手机主屏幕的用户会一直读旧缓存，看不到更新。

本地调试时应用不会注册 Service Worker，避免缓存干扰改动验证。

## 部署到 GitHub Pages

1. 把本目录推送到一个**公开仓库**（公开仓库才能免费启用 Pages）
2. 仓库 Settings → Pages → Source 选 `Deploy from a branch`，Branch 选 `main` / `(root)`
3. 等构建完成，访问 `https://<用户名>.github.io/<仓库名>/`

数据仓库与页面仓库分开：页面公开，数据私有。
